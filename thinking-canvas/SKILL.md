# Thinking Canvas

Use the four basic actions as the default thinking order:

```text
定义 -> 分类 -> 比较 -> 因果
```

Do not add an elaborate framework before these four actions are clear. Decision, workflow, relationships, complex systems, analogy, and iteration are applications or extensions of the four actions.

## Core Actions

### 1. Definition

Write `concept = description`.

- Keep the concept on the left necessary.
- Make the description on the right accurate and unambiguous for the current context.
- State the scope or perspective when a concept has multiple valid definitions.
- Expand a term only when it remains ambiguous or blocks the next judgment; do not recursively define every familiar word.
- Separate a definition from a goal, a standard, and an SOP.

Use this output:

```text
Concept:
Definition:
Boundary / what it is not:
Example and counterexample:
```

### 2. Classification

Classify a collection for a stated purpose. First name the collection and the classification standard.

- Make sibling categories reasonable: use one standard and avoid overlap.
- Make the set complete enough for the current analysis; identify material omissions.
- Do not mix levels, objects, actions, evaluations, or causes in one list.
- Permit multiple classifications of the same object when they serve different purposes.

Ask: “What does this classification need to support: understanding, recording, comparison, or a decision?”

### 3. Comparison

Compare only objects in the same category and on the same property.

- Mark whether each criterion is subjective or objective.
- Prefer measurable evidence when a disputable decision depends on the result.
- When multiple objective criteria matter, rank their importance, assign explicit weights if useful, and compare the total result.
- Do not invent precision. A weighted score records current judgment; it does not create objective truth.
- Accumulate and update criteria over time.

Use this output:

```text
Objects and common category:
Shared properties / criteria:
Evidence and uncertainty:
Importance or weights:
Comparison result:
```

### 4. Causality

Treat sequence and correlation as clues, not proof. Use the everyday four-question test:

```text
Is A really a cause of B?
If so, is A the only cause?
If not, what other causes exist?
If A is not the most important cause, what is?
```

Separate facts, causal hypotheses, alternative explanations, and unknowns. For important claims, seek domain-appropriate evidence rather than treating this checklist as proof.

Do not reduce reality to one-to-one causality. Check for:

- one cause producing multiple results;
- multiple causes producing one result;
- reciprocal causality and feedback;
- time as an indispensable dimension in an evolving system.

For uncertainty, use Bayesian thinking in plain language: new evidence may increase or decrease confidence in a hypothesis. Updating confidence does not itself establish causality.

## Use the Four Actions

### Understand a Concept

Use this sequence:

```text
Definition: What does it mean?
Classification: What parts, types, or neighboring concepts exist?
Comparison: What is it similar to and different from?
Causality: What problem does it explain or solve, and why?
Application: Where can it be used?
Update: What new example, counterexample, or correction changes the model?
```

Teach one unresolved distinction at a time unless the user requests a full overview. For ongoing learning, include a compact progress line showing completed concepts and the current concept.

### Make a Decision

A decision is the combined application of the four actions, not a fifth replacement for them.

```text
Define the matter and its boundaries.
Classify options, criteria, risks, and possible causes.
Compare options on shared criteria.
Analyze the likely causes and consequences.
Choose an action and state the reasons.
```

The user’s purpose, constraints, and time horizon may be needed to make a useful decision, but do not impose a large decision canvas when a simple decision needs only the four actions.

### Design a Workflow or SOP

Use What / Why / How:

- What: define the task and its completion condition.
- Why: state the decision or result the task serves.
- How: decompose the work.

Build the How only from these three modules:

```text
Sequence: steps that must happen in order.
Loop: steps repeated until a condition is met.
Judgment / branch: different steps for different conditions.
```

After decomposition, identify serial dependencies and tasks that can run in parallel. Keep the SOP as simple as possible and attach a verification point to each branch or completion condition.

## Extensions

Use these only when the question needs them.

### Relationships

After defining concepts, name their relationships rather than leaving them implicit: membership, common membership, intersection, AND/OR/NOT, parallel/progression/contrast, greater-than, approximately-equal, causality, correlation, or no meaningful relationship.

### Analogy

Use a familiar A to understand unfamiliar X only as `X ≈ A`, never `X = A`. State which property transfers and which boundary does not. Then reverse the question: “Where else might this principle apply?”

### Development and Iteration

Distinguish iteration from repetition: the output of one round becomes the input of the next. Use small rules plus repeated feedback; do not pretend to know the final outcome of a complex system in advance.

### Three Tables

Treat meaningful learning and practice as CRUD on three tables:

```text
Concept table: cognition — what is it?
Relationship table: judgment — how are things connected, different, or important?
Workflow table: action — how is the task carried out?
```

At the end of a learning or analysis task, state what was created, read, updated, or deleted in these tables. If none changed, the work likely produced no reusable learning.

## Response Discipline

- Start with the relevant action, not a generic summary.
- Keep teaching interactive and incremental when the user is learning; do not dump every section of this skill by default.
- For a full analysis, explicitly show `Definition -> Classification -> Comparison -> Causality -> Decision/Workflow` so the reasoning order stays visible.
- Preserve the distinction between source facts, user preferences, inferences, and unresolved questions.
- Do not claim a conclusion is certain when evidence is incomplete.
